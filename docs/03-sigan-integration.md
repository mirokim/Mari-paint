# Mari Paint ↔ Sigan (VASE9) 연동 설계

> 대상: [`mirokim/VASE9`](https://github.com/mirokim/VASE9) — 제품명 **Sigan**, 작업 과정 증명 서비스
> 조사 기준 커밋: `d5267fa` (2026-09-17)
> **결정: 두 제품은 분리한다. 대신 완벽하게 맞물린다.**

---

## 1. 제품 목표

**Mari Paint의 목적 중 하나는 "Sigan과 완벽하게 같이 작동하는 것"이다.** 부가 기능이 아니라 제품 정의다.

이게 말이 되는 이유: Sigan은 포토샵·CSP 안으로 들어갈 수 없어서 **밖에서 HID를 훔쳐본다.**
그래서 캔버스 좌표도, 픽셀도, 레이어도 모른다. Mari는 **안에 있다.** 그냥 알고 있다.

> **Mari Paint = Sigan이 완전한 증거를 얻을 수 있는 유일한 페인트 툴.**

### 1.1 왜 내장하지 않는가 (2026-09-17 결정)

| 이유 | 내용 |
|---|---|
| **라이선스** | VASE9는 `LICENSE` 파일이 없다(= all rights reserved) + 구독·B2B·후원이 걸린 상품. Mari는 Apache-2.0. 기록기를 오픈소스에 넣으면 **누구나 서명 로직을 고쳐 빌드**할 수 있다 |
| **위조 방어** | Sigan의 완화책이 *"서명 바이너리"* 다 — 소스가 없어 리버싱이 귀찮다는 것. 오픈소스는 그 장벽을 0으로 만든다. 되돌릴 수 없다 |
| **고객** | Sigan의 사용자는 CSP·포토샵 작가다. 내장하면 Mari 작업만 인증하게 된다 |
| **스택** | Sigan은 .NET 8 WPF, Mari는 C++/Qt. .NET 런타임을 얹으면 콜드스타트 1.5초·설치 80MB 목표가 깨진다 |
| **증인 수** | 그리는 놈과 증명하는 놈이 같은 바이너리면 대조할 대상이 없다 |

## 2. 경계선 — 누가 무엇을 하는가

이 표가 이 문서에서 제일 중요하다. **여기서 벗어나는 구현은 리뷰에서 막는다.**

| | Mari Paint | Sigan |
|---|---|---|
| 획·필압·틸트 **발생** | ✅ | |
| 캔버스 좌표·레이어·브러시 **부여** | ✅ | |
| 픽셀 스냅샷 해시 **계산** | ✅ | |
| 저장 파일 해시 **계산** | ✅ | |
| 뷰 변환(줌·회전) **보고** | ✅ | |
| 로컬 무서명 로그 **보관** | ✅ | |
| **해시체인 봉인** | ❌ | ✅ |
| **기기 키 서명 (ES256)** | ❌ | ✅ |

| 신뢰 등급 판정 | ❌ | ✅ |

**Mari는 절대 증명하지 않는다. 증명 가능한 형태로 그릴 뿐이다.**

## 3. 입력 API — WinTab 금지 (타협 없음)

Sigan의 `Core/Foreground.cs`에 **`WinTabKeywords`** 라는 목록이 있다.
여기 올라간 앱은 *"RawInput이 침묵하니 프록시 DLL을 주입해야 하는 앱"* 이다.

```
{ "clipstudio", "zbrush", "opencanvas", "tvpaint", "harmony",
  "toonboom", "painter", "photoshop", "krita" }
```

**Krita가 왜 저기 있는지가 우리한테 하는 경고다.** 코드 주석 그대로:

> krita: 포토샵과 **같은 이유로 같은 실수를 했던 자리**다. 오픈소스라 Windows Ink를 쓸 것으로
> 짐작하고 목록에서 빠져 있었는데, 실측하니 아니었다 — Krita 5.3.3 프로세스가 `wintab32.dll`과
> `Wacom_Tablet.dll`을 로드한 채로 돌고 있다. **Windows Ink는 설정에서 켜야 하는 선택지이고
> 기본값이 아니다.**

포토샵도 마찬가지다 — 와콤이 필압 문제 해법으로 널리 권장하는 `UseSystemStylus 0` 설정이
포토샵을 WinTab 모드로 돌린다.

### 결정

| | 정책 |
|---|---|
| **기본** | **Windows Ink (WM_POINTER)** — 고정. 설정 없음 |
| **WinTab** | **구현하지 않는다.** 필요해지면 그때 고급 설정 + 경고로 |
| **검증 목표** | **Mari는 `WinTabKeywords`에 영원히 올라가지 않는 최초의 드로잉 앱이 된다** |

마지막 줄이 이 문서에서 유일하게 **외부 리포로 검증 가능한** 목표다.
Mari 프로세스가 `wintab32.dll`을 로드하면 CI에서 빌드를 깬다.

## 4. 3채널 구조

전부 COM으로 하면 안 된다. 스트로크 점은 **초당 수백 개**다.

```
┌─────────────────────────┐                      ┌─────────────────────────┐
│      Mari Paint         │                      │    Sigan Recorder       │
│        (C++/Qt)         │                      │     (C# WPF .NET8)      │
│                         │  ① 제어 · 저빈도       │                         │
│  COM: IMariApplication ◄┼──────────────────────┼─ C#은 COM 인터롭 내장     │
│                         │                      │                         │
│  파이프 클라이언트 ──────┼──────────────────────┼─► 명명 파이프 서버        │
│                         │  ② 스트로크 · 고빈도   │   (WinTabBridge 패턴)   │
│                         │                      │                         │
│  IMariEventSink ───────┼──────────────────────┼─► ③ 이벤트 · 중빈도       │
└─────────────────────────┘                      └─────────────────────────┘
```

| 채널 | 방식 | 빈도 | 이유 |
|---|---|---|---|
| ① 제어 | COM `IMariApplication` | 세션당 몇 번 | C# COM 인터롭이 언어 내장 |
| ② 스트로크 | 명명 파이프 `sigan-native` | 초당 수백 | COM 마샬링은 16ms 예산을 깬다 |
| ③ 이벤트 | COM 연결점 `IMariEventSink` | 분당 몇 번 | 저장·뷰변경·붙여넣기 |

### 4.1 스트로크 프레임

Sigan의 기존 `WinTabBridge` 규약을 따른다 — **파이프 ACL을 현재 사용자로 제한 + 32바이트 세션 토큰
핸드셰이크 + 고정 길이 프레임.** 검증된 걸 새로 만들 이유가 없다.

| 필드 | 크기 | 비고 |
|---|---|---|
| `seq` | 8B | **단조 증가 시퀀스** — 유실 탐지용 (4.2 참조) |
| `t` | 8B | 세션 시작 기준 ms, **단조 시계** (5.6 참조) |
| `cx, cy` | 8B | **캔버스 좌표** — 줌·회전·팬과 무관한 불변값 |
| `p` | 4B | 필압 0~1 |
| `tiltX, tiltY` | 8B | 각도(°) |
| `rotation, velocity` | 8B | 펜 회전, 속도 |
| `layerId`, `brushId` | 8B | |
| `flags` | 4B | down / move / up / eraser |

**캔버스 좌표가 핵심이다.** 지금 Sigan은 화면 좌표뿐이라 작가가 캔버스를 회전·줌하면 같은 획이
다른 궤적으로 남는다. 그래서 `Vase9.ViewProbe`·`Vase9.TabOcrProbe`로 화면을 뜯어보고 있다.
캔버스 좌표로 주면 **그 문제 자체가 사라진다.**

### 4.2 🔴 오버플로 정책이 달라야 한다

기존 `WinTabBridge`는 이렇게 한다:

```csharp
if (_q.Count < 8192) { _q.Enqueue(s); Packets++; }
else Dropped++;          // ← 조용히 버린다
```

**HID 경로에선 맞다** — 그건 연속 신호의 *샘플링*이라 몇 개 빠져도 획 모양이 산다.
**네이티브 경로에선 틀리다** — 이건 샘플이 아니라 **정본 기록**이다. 버리면 증거에 구멍이 난다.

| | HID 경로 | 네이티브 경로 |
|---|---|---|
| 성격 | 샘플링 | **정본** |
| 오버플로 | 드롭 OK | **드롭 금지** |
| 대응 | `Dropped++` | **디스크로 스풀 → 나중에 이어붙임** |

Mari는 파이프가 막히면 **로컬 저널에 쓰고 seq를 유지**한다. Sigan은 seq 구멍을 보고
"유실 있음"을 로그에 정직하게 남긴다. 조용히 넘어가지 않는다.

## 5. "완벽하게 같이 작동"의 정의

말로만 두면 안 지켜진다. **6개 조건으로 쪼개고 각각 설계한다.**

### 5.1 무설정 — 사용자가 아무것도 안 한다
- Mari 시작 시 `sigan-native` 파이프 존재를 **폴링하지 않고** 연결 시도 → 실패하면 조용히 로컬 모드.
- Sigan이 나중에 켜지면 Sigan이 **브로드캐스트** → Mari가 붙는다. (반대 방향도 지원)
- 설정 화면에 "Sigan 연동" 토글은 **두지 않는다.** 끌 이유가 없다. 상태 표시만 한다.

### 5.2 무손실 — 획을 하나도 안 잃는다
- 4.2의 드롭 금지 정책.
- 파이프 쓰기는 **논블로킹** — 절대 그리기 스레드를 막지 않는다. 막히면 저널로 간다.

### 5.3 끊겨도 안 잃는다 — 재연결
Sigan은 Velopack **자동 업데이트**를 쓴다. 그림 그리는 중에 재시작할 수 있다는 뜻이다.

```
연결 끊김 감지
   → Mari는 계속 그린다 (절대 방해하지 않는다)
   → 로컬 저널에 append, seq 유지
   → Sigan 복귀 → 재핸드셰이크 (새 세션 토큰)
   → Mari가 "seq N부터 M까지 밀린 게 있다" 통보 → 밀어넣기
   → Sigan이 시간 순서대로 병합
```

**핵심: 재연결이 새 구간(Segment)을 만들면 안 된다.** Sigan의 `Segment`는 "전원off·다른기기·
다른작업"의 경계인데, Sigan이 업데이트로 재시작한 건 작가 입장에서 아무 일도 아니다.
→ 프레임의 `seq` 연속성으로 **같은 구간임을 증명**한다.

### 5.4 크래시 안전
- 로컬 저널은 **append-only**. 획 끝(`up`)마다 flush.
- Mari가 죽어도 저널이 남는다 → 재시작 시 발견 → Sigan에 제출.
- 전원이 나가도 마지막 획까지는 산다. (매 점마다 fsync는 안 한다 — 16ms 예산을 깬다)

### 5.5 독립 업데이트 안전 — 버전 협상
**두 앱은 따로 배포되고 따로 업데이트된다.** 한쪽이 올라가도 다른 쪽이 깨지면 안 된다.

핸드셰이크에서 능력을 교환한다:

```
Mari  → Sigan :  { proto: 1, app: "mari-paint/0.3.0",
                   caps: ["canvas-xy","layer","brush","pixel-hash","view"] }
Sigan → Mari  :  { proto: 1, app: "sigan/0.2.46",
                   accepts: ["canvas-xy","layer","view"] }        ← pixel-hash 모름
```

규칙 3개:
1. **필드는 더하기만 한다.** 빼거나 의미를 바꾸지 않는다.
2. **모르는 필드는 무시한다.** 에러가 아니다.
3. **`proto`가 다르면** 공통 최소로 내려간다. 연결을 끊지 않는다.

→ 구버전 Sigan + 신버전 Mari 조합에서도 **기록은 계속된다.** 품질만 낮아진다.

### 5.6 시계 안전
- 프레임의 `t`는 **단조 시계**(`QueryPerformanceCounter`) 기준 상대 ms.
- 벽시계는 **세션 시작 시 한 번만** 앵커로 보낸다.
- 이유: NTP 동기화가 그리는 중에 시계를 점프시키면 상대 시각 기록이 오염된다.
  Sigan의 `Stroke.Points`가 이미 상대 ms라 궁합이 맞는다.

## 6. Sigan이 없을 때 — 승격 경로

Mari 사용자 전부가 Sigan을 쓰진 않는다. 그래도 **기록은 남긴다.**

```
Sigan 미설치
   → Mari가 .ora 안에 무서명 과정 로그를 남긴다
   → 신뢰 등급: "기록 있음" (인증서 아님, 그렇게 표기한다)
        │
        ▼ 나중에 Sigan 설치
   → Sigan이 로그를 발견 → 검증 → 체인 봉인 + 서명
   → 신뢰 등급: 사후 서명 (실시간 앵커가 없으므로 native보다 낮다)
```

| 등급 | 조건 | 비고 |
|---|---|---|
| `native` | Mari 직접 발행 + Sigan 실시간 수신 + 서명 | **최상** |
| `rawinput` | Sigan이 밖에서 HID 관찰 | 현행 CSP·PS |
| `deferred` | Mari 로컬 로그를 사후 제출·서명 | 실시간 앵커 없음 |
| `unsigned` | Mari 로컬 로그만 | 인증서 아님. 그렇게 표시 |

**`deferred`를 `native`로 올려주면 안 된다.** 사후 제출은 편집 기회가 있었다는 뜻이다.
Sigan 문서 08의 원칙 — *"막을 게 아니라 정직하게 드러낸다"* 를 따른다.

## 7. 두 증인 구조

3절 결정(Windows Ink 고정) 덕분에 **Sigan의 RawInput 경로가 Mari 사용 중에도 살아 있다.**

```
              ┌── ① Mari 직접 발행  (캔버스 좌표 · 레이어 · 픽셀 해시)
   같은 획 ──┤
              └── ② Sigan RawInput (HID 원시 신호 · 화면 좌표)

   Mari가 보고한 뷰 변환으로 ①↔② 상호 변환 가능 → 대조할 수 있다
```

Sigan이 스스로 인정한 약점:

> **"기록기 자체 변조"는 원리적 완전방어 불가(🟠).** 서명 바이너리 + 감독 세션 스팟체크로 완화.

두 증인이 이걸 완전히 풀진 못한다. 하지만 위조하려면 **독립된 두 경로를 시간·좌표까지 맞춰
동시에** 속여야 한다. 비용이 크게 오른다.

어긋나면? **숨기지 말고 "경로 불일치"로 표시한다.** 등급을 낮추되 조용히 넘어가지 않는다.

## 8. `.sigan` 스키마 변경

기존 v0.2를 **깨지 않는다.** 선택 필드만 더한다.

```csharp
public sealed class Segment {
    // ... 기존 그대로 ...
    public string? Source { get; set; }        // "rawinput" | "wintab-proxy" | "native" | "deferred"
    public string? SourceApp { get; set; }     // "mari-paint/0.3.0"
    public List<ViewTransform>? Transforms { get; set; }   // native 일 때만. 좌표 대조용
    public long? LostFrames { get; set; }      // seq 구멍 — 정직하게 남긴다 (4.2)
}
```

> ⚠️ **서명 정본(SigPayload) 주의.** `VaseLog.cs` 주석이 경고한다 — C#(`Core/Recording.cs`)과
> 웹(`lib/signature.ts`)이 **같은 입력에 같은 바이트**를 내야 한다. 예전에 `DeviceInfo`가
> `null`이냐 `new()`냐로 두 언어가 갈려 골든 테스트가 잡은 전례가 있다.
>
> 규칙: **스키마를 건드리면 공유 골든 테스트부터 고친다.** 필드는 기존 `:src` 선례대로
> **있을 때만 서명에 붙여** 옛 인증서 바이트를 보존한다.

`Stroke.Points`는 `[t, x, y, p, tiltX, tiltY]` **그대로 둔다.** 배열 길이를 바꾸면 서명 바이트가
깨질 위험이 크다. 레이어·브러시는 별도 병렬 배열로 넣는다.

## 9. 단계별 계획

| 단계 | 내용 | Mari 마일스톤 | 검증 |
|---|---|---|---|
| **S0** | Windows Ink 고정 | M1 | Sigan RawInput이 Mari 획을 잡는다. `wintab32.dll` 미로드 |
| **S1** | `sigan-native` 파이프 + 저널 | M1~M4 | 캔버스 좌표 획이 `.sigan`에 들어간다. 드롭 0 |
| **S2** | COM 이벤트 싱크 | M4 | 저장 시 `Outputs` **자동** 채움 |
| **S3** | 픽셀 스냅샷 해시 | M4 | `StartCanvasHash`/`EndCanvasHash`가 **v0 null을 벗어난다** |
| **S4** | 두 증인 대조 + `native` 등급 | M5 | 검증 페이지에 경로 일치 표시 |

**S0가 제일 중요하고 제일 싸다.** Mari가 Windows Ink만 쓰면 연동 코드 한 줄 없이도
Sigan이 오늘 당장 Mari를 기록한다. 나머지는 전부 품질 향상이다.
